## 二、技术架构

```
Electron 45.4.1（main.js 外壳，TS/JS）
  ├─ app://chat 自定义特权协议 → 托管 web\（前端静态产物）
  │    standard + secure + supportFetchAPI + corsEnabled
  ├─ 数据目录 = exe 同级 data\（userData / sessionData 都指过去）
  ├─ 原生标题栏 + DWM 着色（koffi → dwmapi.dll）
  ├─ API Key：DPAPI(safeStorage) 加密存 secret.dat，preload 启动注入
  └─ 无备份、无本地代理、无轮询
前端：React 18 + Zustand + Rspack，构建期注入 __API_ORIGIN__=https://api.deepseek.com
```

**为什么直连官方 API**：实测该服务对任意 Origin 返回 `access-control-allow-origin`，
`app://chat` 也在内，所以不需要代理；流式/中断交给 Chromium 原生处理最稳。

## 五、踩坑记录（现象 → 原因 → 结论）

### 数据与存储
1. **网页版"记录丢了"** → 浏览器按 origin 分柜子，换入口即换柜子；且网页版无云端。
   → 本地版固定 `app://chat` 一个 origin，数据落磁盘，问题从根上消失。
2. **origin 必须 `standard:true`** → 否则没有 origin，IndexedDB 直接不可用。
3. **备份是过度设计** → 用户只要"一份数据一直在"。备份与数据同目录也防不了误删。
   → 自动/手动备份全删掉，只保留应用自带的导出。

### 打包与环境
4. **npm 11 拦截 install 脚本** → electron 二进制、koffi 原生模块不会自动装。
   → 手动 `node node_modules/electron/install.js`（配 `ELECTRON_MIRROR=npmmirror`）。
5. **electron-builder 从 GitHub 下 winCodeSign 会卡死** → `signAndEditExecutable:false`，
   自己从镜像下 rcedit 写图标与版本信息。
6. **`ELECTRON_RUN_AS_NODE=1`（宿主环境带入）** → exe 以 Node 模式启动，报 `app.getPath` undefined。
   → 测试命令里清掉该环境变量；用户双击不受影响。
7. **部署时程序在运行** → 覆盖文件被占用，出现"删了没补"的半损坏安装。
   → `build.ps1` 开头与部署前都检查进程与文件占用，先报错退出，绝不半途而废。
8. **Windows 10 上报 ProductName 但 build 26300** → 实为 Win11，DWM 接口可用。

### 标题栏
9. **`setTitleBarOverlay` 只在 `titleBarStyle:'hidden'` 时有效** → 它管的是"按钮区"，不是标题栏背景。
10. **原生标题栏颜色 Electron 管不了** → Win11 的 `DWMWA_CAPTION_COLOR(35)` / `DWMWA_TEXT_COLOR(36)`
    可指定，通过 koffi 调 dwmapi 实现；COLORREF 是 `0x00BBGGRR`，内存按 B,G,R,0。
11. **DWM 颜色会在窗口激活/重绘时被冲掉** → 表现为"切出去再回来变系统色，过一会儿又变回来"。
    → 在 `focus/blur/show/restore/maximize/unmaximize` 后重写，并在 +400ms、+1200ms 各补一次
    （Windows 重绘是异步的，且不会通知我们"我丢了你的颜色"）。

### 主题
12. **菜单栏变黑条** → 菜单栏颜色由 Electron 的 `nativeTheme` 决定，默认跟系统，不跟应用内开关。
13. **强制 `themeSource` 会掐死"跟随系统"** → 应用判断系统深浅色靠 `prefers-color-scheme`，
    而 `themeSource` 正是它的上游。→ 必须按**用户偏好**映射（system 就不干预），不能按当前颜色。
14. **轮询是症状不是解法** → "手动深色 → 跟随系统"时颜色不变、语义变了，轮询只能慢半拍。
    → 让 `settings.ts` 派发 `ds:settings` 事件，去掉全部 `setInterval`，延迟 83ms → 5ms。

### 渐变（已撤回，不要再试）
15. **给所有元素挂 transition** → 整页每帧重绘 + 文字抗锯齿被临时关闭 → 观感"整页刷一下"。
16. **纯色遮罩淡出** → 内容被完全盖住再揭开，眼睛会捕捉到"内容消失" → 更怪。
    → 要真正做对必须"异步切换 + 截图交叉溶解"，代价是改应用时序 + 跨进程传图，不值得。

### 验证与自检
17. **探针写进应用会话表会污染用户列表** → 改用独立数据库 `__ds_probe`，用户永远看不到。
18. **截图验证** → `PrintWindow` + `SetProcessDPIAware()` 才能抓到含标题栏的整窗；
    其像素是 BGRA（读 R 通道得到的是实际 B）。
19. **“更多”菜单会飘到左上角** → 三点按钮只在会话行悬停时 `display:flex`，鼠标移进菜单后
    行失去悬停、按钮变 `display:none`，锚点 rect 成了 0×0，定位逻辑据此算出 (8,4)。
    → 在 `useAnchoredPosition` 里判断空矩形并保留上一次位置（对所有锚定浮层生效）。

### 沟通
19. **"把文字换成图标"被理解成"换成另一段文字"** → 用户要的是把 `API 使用 demo` 换成网页版 logo。

## 六、已否决的方案（不要重提）

| 方案 | 否决理由 |
|---|---|
| 自动/手动备份 | 用户明确不需要，数据只留一份 |
| 本地 API 反向代理 | 实测 CORS 通过，多一层只多故障点 |
| WCO 自绘标题栏 | 用户要原生标题栏（贴靠分屏、拖动、双击都要原生） |
| 自绘三个窗口按钮 | 失去 Win11 贴靠布局 |
| 主题切换渐变 | 见坑 15/16，观感反而更差 |
| 内嵌官方网页版（独立窗口 + persist 分区） | 官网在登录页直接拦截 Electron 环境，弹「使用环境异常……建议使用官方产品」。窗口/分区/渲染都正常，是对方刻意的安全策略；伪造 UA 有账号被标记的风险，不做 |

## 七、当前已知限制

0. **切回焦点时标题栏可能闪一帧系统色（未解决，已缓解）**：在设置弹窗打开的情况下，
   从别的程序切回来，标题栏会极快地闪一下系统个性化色。用两种方式（程序化置前、
   模拟 Alt+Tab）各采样 140 / 200 次（约 4ms 一次）均未复现，怀疑是激活瞬间被系统或
   Chromium 覆盖 1~2 帧的竞态。已把重写节奏改为 `0/8/16/32/64/128/400/1200ms` 密集补偿；
   若仍出现，唯一根治手段是 koffi 子类化窗口过程（有崩进程风险，暂不做）。

1. 标题栏着色仅 Win11（22000+）；Win10 回退系统配色，功能不受影响。
2. 依赖 koffi 原生模块：加载失败同样回退系统配色，不会崩。
3. 无代码签名：他人首次运行可能遇 SmartScreen，点"更多信息 → 仍要运行"。
4. 仅 Windows x64。
5. 分发前必须删掉 `data\`，否则会把你的 API Key（localStorage 明文）和全部对话发给对方。
